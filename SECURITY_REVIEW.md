# Static security review — ICARUS Unified World Phase 1 Lite

Reviewed source: thekiddam-code/munza69, commit c73c7da49e19fe82b2fb8028cbd6fc30915d2864. All 43 retained runtime files are byte-for-byte copies. Lite changes packaging, not runtime security behavior. This is a source review and limited functional check, not an antivirus certification, penetration test, dependency vulnerability audit or guarantee against false positives.

## Commands, network destinations and disk changes

The launcher executes only the local Python server. Runtime Python does not invoke subprocess/Popen, os.system, shell=True, PowerShell, cmd scripts, registry editors or arbitrary command interpreters. Configured keyboard input can nevertheless perform actions in the foreground application, so authenticate only devices you trust. The manually documented `py -m pip install -r requirements.txt` command installs Python packages and their dependencies into the selected environment; the launcher does not install them automatically.

Normal application traffic is the local HTTP receiver and same-origin browser API traffic. The optional TV destination is a user-configured private IPv4 address. Web assets are local; SVG data URLs are embedded content, not network callbacks. Base64 in the server encodes the TV client name for its protocol. No runtime eval/new Function or encoded shell payload was identified in the retained first-party code. Third-party library code is retained with its upstream license, not independently certified.

Expected host disk writes: `config.json` (including default creation if missing), atomic `.tmp` replacements for edited configuration, `paired_devices.json` containing token hashes, and `samsung_tv.json` containing the configured IP and TV token in plaintext. These generated device files are not supplied in the distribution. Browser databases, local/session storage and user-requested Downloads JSON files are additional writes. Clipboard/game state can change through intentional remote actions.

No reviewed runtime command installs a startup service, scheduled task, registry setting, driver, firewall rule or antivirus exclusion. There is no antivirus-disabling or evasion step in this build process or distribution. Windows may independently display a normal network-access prompt; the package does not approve or modify that policy for you.

## Distribution and verification limits

Standalone test suites, historical test results, development utilities and packaging scripts are excluded from the Lite ZIP. The existing browser's embedded diagnostic mode and the two JavaScript diagnostic assets remain because the unchanged application loads/references them. They are not separate test runners. Removing them would require a runtime code change rather than this source-faithful packaging operation.

The ZIP uses ordinary transparent compression; no executable wrapper, obfuscation or password is added. SHA-256 establishes download identity, not a malware-free guarantee. No antivirus engine scan was available in this Linux environment. Do not disable antivirus or add exclusions to make this package run. If protection flags it, retain the detection details and seek review of the readable source/vendor finding.

Functional testing stubs desktop input and the TV socket and uses Android-style mobile/touch emulation. Physical Windows input, the Windows BAT launcher, a physical Android device/Wi-Fi path, real TV TLS interoperability, hostile-network penetration testing and third-party dependency audits were not verified. See the separate release verification report for exact measured results.
