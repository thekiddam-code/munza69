# UMBRA Mobile 3.1 — independent controls and Phase 4.9 bulk audio

This increment updates the existing native launcher; it does not rebuild it or replace the ICARUS simulation. The six destinations remain **HOME | APPS | DECK | SIMULATOR | ICARUS | CONFIG**.

## What changed

- DECK contains Engineering and Device controls. Dedicated Command library and Instant Buttons navigation are removed. Existing command definitions and mappings remain available to HOME widgets and game controls.
- SIMULATOR contains Rocket League, Fortnite, Minecraft, **Soundboard**, and Simulation. Soundboard output configuration remains under **CONFIG → ICARUS → Soundboard → Audio Output**, authoritative on the PC.
- HOME has independently configurable **Button widget** and **Soundboard** instances, including multiple instances on one page or in different presets. Each keeps its own title, selection, group, columns, height, accent, transparency, placement, size, and collapsed state. A custom definition or override saved from a widget changes only that instance. Sound labels, playback IDs, output settings and optional server favorites retain their existing ICARUS source of truth.
- HOME page density now supports 2–8 columns (global default 3–8). Actual columns adapt to available width using a minimum 54 dp cell rather than shrinking targets indefinitely. Widgets span up to 8 columns / 12 rows; button widgets use at least 3 rows. Inner button grids support 1–6 columns and 56–96 dp heights. A 432 dp phone may render 7 outer columns when 8 are requested. Dense labels wrap and grids scroll; physical readability remains a device check.
- **CONFIG → ICARUS** includes a masked current server PIN field. Save the server address first, enter its PIN, and pair. The field is cleared after submission and when leaving visibility. Only the existing server-bound, Keystore-encrypted token is retained; PINs never enter DataStore/export.
- A small **||| Recent apps** icon sits at the right of the footer. Hide it in CONFIG → Appearance. It uses Android's supported Accessibility global Recent apps action and requires explicit manual enablement of **UMBRA Recents** in Android Accessibility settings. The service does not retrieve window content, control gestures, filter keys or record events. If not enabled, tapping opens setup guidance; the original Samsung bar remains usable. Android 13+ may require the app's **Allow restricted settings** action for sideloaded apps before Accessibility can be granted. No grant is automated or bypassed. Native Recents behavior on S24+ remains unverified.

## Arrange your widgets

1. Long-press a HOME page title, choose Add widget, then Button widget or Soundboard.
2. Long-press the widget header and choose Configure. Name it, choose a group such as Rocket League or Fortnite, select buttons, and set appearance/density/size. Save applies the draft atomically; cancel leaves it unchanged. Add custom button stores a definition only inside that widget.
3. For sounds, Sync retrieves the original PC library; select the sounds for that instance. Favorites-only is optional and uses the PC's shared favorite flags. There is no six-button limit.
4. Long-press a widget header to move it, including while collapsed. Long-press a button to edit its own inner grid/override. Available amber cells appear only during editing. Undo, resizing, page movement and preset switching retain the existing arrangement engine. Animation master off does not disable editing or change Visual Detail.

Selections are stable action IDs, not array indices. Schema 6 reads schemas 2–6 and preserves prior presets, bindings, URLs, mappings, global definitions and audio preferences. Existing legacy shared selections/favorites initialize older button widgets that lack independent selections; explicit per-widget selections win. Old global manager fields and TV mappings are retained for round trips, with obsolete navigation hidden and TV execution blocked. A button absent from the current catalog is retained as an unresolved selection rather than silently reassigned. Export includes local instance settings but no PIN/token/audio output.

## PC website: Phase 4.9 on port 8765

[Separate update package](../pc-update/phase49/README.md) targets the exact inspected Phase 4.9 source at `780108d56646982c323b3a4b82c74a2268a0bd60`. The cloud environment could not connect to the user's private PC site. **It has not been deployed to that PC.** Apply the supplied ZIP locally after saving the voyage and stopping the original companion normally. The installer verifies matching source, saves the original four code files and runs the existing verified sound-library backup before modifying code. It refuses mismatched/partial source or missing/corrupt previously populated libraries. An explicit new-library option is for genuinely new installations only.

The PC Soundboard gains **Add many sounds**: multi-file/folder selection, category/clip volume, permission confirmation, serial import, progress, per-file errors, default duplicate skipping and cancellation. Limits are 512 library entries / 256 MiB total; each original source remains at most 8 MiB / 30 seconds. The original browser PCM converter and authenticated import service perform the work. Acknowledged saves remain if later files fail. Authentication/revision conflicts and unconfirmed requests stop the queue without automatic replay. Duplicate hashing happens on the server so HTTP LAN access works without Web Crypto. The native catalog response bound supports this larger library.

Only `web/umbra/soundboard.js`, `sound_library.py`, `sound_backup.py`, and `sound_service.py` are patched. Existing schema-1 WAVs, IDs, labels, metadata, pairing and output/audio-profile files are retained. There is no new playback engine, telemetry collector, world/save migration, microphone injection, driver, Sonar/default-device change or TV backend deletion. Shared audio backups remain private. Old 64-sound builds cannot read an expanded library: rollback code is blocked until a compatible, verified pre-import library is restored separately. Read the PC package README before applying.

## Build, verification and limits

Version **3.1 / code 7**, package `com.umbra.mobile`, min API 29 / target API 35. Install over the previously distributed signed APK to preserve data. Choose Samsung Settings → Apps → Choose default apps → Home app → UMBRA; choose One UI Home there to restore Samsung. Build with the included Gradle wrapper / `build_umbra.bat`, SDK 35 / Build Tools 35.0.0, and JDK 17 or 21.

[Executed evidence](verification/widgets31/RESULTS.txt) records the exact final build, 97 Android test executions, lint and APK signing checks. Native SDK 30/34 host tests cover independent Rocket/Fortnite and sound widgets, exact HTTP command/playback routes, widget drafts/overrides, PIN setup and credential exclusion, Recents setup and service privacy flags. Existing lifecycle, animation, Engineering, grid, provider, soundboard and configuration tests remain in the full run. Device-test APK compilation is not device instrumentation execution.

PC checks: 42 Python service tests, 10 real Chromium/authenticated-handler browser tests and 4 installer tests. Bulk tests save 70 distinct generated sounds, skip a duplicate, reject a broken file, cover cancel/conflict behavior and preserve existing bytes/ID/output/audio profile across restart. The installer is tested against an isolated fixture installation, including backups, refusal paths and safe rollback. Tests do not verify the user's actual private backup/library, audible output, Windows/Sonar routing, voyage save, or site deployment. Windows BAT files are included but not executed on this Linux host.

No physical S24+/Windows hardware acceptance has occurred. Native Home/gesture/Recents behavior, real Keystore and special-access grants, actual game/sound delivery, third-party providers, dense-grid readability at large fonts, Tailscale routing and battery/frame timing remain manual checks. URL address classification does not prove routing. Remote desktop still opens the existing browser interface because inspected APIs do not expose native video/input streaming. No exact One UI animation parity is claimed.

Recommended next work: physical-device acceptance, a consistent release signing workflow, measured dense-grid accessibility/performance, and continued use of the existing companion's advertised capabilities. Do not merge main's older ICARUS runtime over the working Phase 4.9 installation.
