# UMBRA Mobile 3.4: sound after Rocket League chat

Adds **Sound after chat** to the existing Button editor for QuickChat and Text. Long-press a HOME Rocket League/Mixed widget button → Configure → Sync sound choices → select an existing sound (or None) → Save UMBRA override. Each widget instance can choose a different sound without changing neighboring widgets or other presets. Existing custom chat buttons use the same field. The editor shows unavailable saved choices instead of silently selecting a replacement.

Native custom buttons gain optional `afterSoundId`, default empty, validated as an existing-library ID shape. It is included in button files, widget overrides, preset exports and DataStore through the existing configuration machinery. Schema 7 is retained with this additive optional field; existing settings do not reset. No output-device or volume copy is saved on Android. Other output types retain their behavior. Category colors/icons and fullscreen behavior are unchanged.

Attached chat goes to the new paired `/api/rocket/chat-sound` endpoint as one request. The PC executes the existing chat input routine fully, including Enter for typed messages, and then asks the original SoundService to play the existing sound using the saved output/processing. No second soundboard, connection manager, background service or polling loop is introduced. Native errors distinguish a missing PC update; no automatic replay/fallback occurs. Receipts on the host protect repeated request IDs for a bounded window.

The separately packaged **phase49-chat-sounds** PC update applies on top of the previous **phase49-host-actions** update. It patches only the matching server.py and adds one sequencing module. It retains all existing settings/library/audio profiles, host actions, bulk import and simulation data. See its [install/API/rollback instructions](../pc-update/phase49-chat-sounds/README.md).

Verification is recorded in [executed results](verification/chat34/RESULTS.txt). Tests cover request authentication, endpoint choice, UUIDs, optional defaults/validation, preset/widget independence/export and real native selection/persistence/None controls, as well as host event ordering, missing sounds, input failures, deduplication, auth/origin guards and installer rollback. Physical Windows/Rocket League input acceptance, actual sound routing/latency and audibility remain device checks. Completing the keyboard routine does not prove the game accepted/displayed a message.
