# Phase 3.5 limitations and release gates

- Native Windows launcher/input, physical Android/Galaxy Tab S5e LAN/touch/GPU, Samsung TV and antivirus engine tests require hardware/software unavailable in this Linux execution environment. Browser emulation, stubbed host I/O and source/hash review are not substitutes. Firefox/Safari and native save-picker interactions remain unverified. No security protection is disabled or bypassed.
- Sustained human story interest, authored art/audio and final audiovisual approval remain unverified release gates. This is procedural 2D motion and an in-app state/reconstruction timeline, not anatomical 3D, voiced cinema or encoded video. No natural Legendary outcome is guaranteed or fabricated.
- Lethal classification is intentionally conservative: retained causal intervention, public death, measured disadvantage/danger, at least 100 observed exposure opportunities with a low observed lethal fraction, and source-linked imagery are required. Recorded opportunity counts begin when this build actually observes eligible windows; none are backfilled into old encounters. Missing evidence excludes a clip; old films are preserved unchanged.
- Source frames (24), rolling snapshots (120), films (12 weeks), SOL entries (48) and interaction memories remain bounded. Full world knowledge/history still grow. Cursor transfers avoid full history arrays in the new path; live world snapshots themselves remain monolithic. Legacy JSON keeps whole-file parsing/128 MiB limit, and legacy/rescue export uses the existing full-read path. Blob fallback retains encoded output bytes; File System Access provides incremental disk output. Streaming has a 64 MiB line bound and 128-row chunks; it is not an unlimited-state guarantee.
- Import requires functioning IndexedDB and an active writer. Failed DB operation cannot safely preserve full history in localStorage, so import fails closed rather than silently dropping it; labeled compatibility rescue export remains. Old save-only backups cannot supply absent older history and are explicitly reported partial. Chunk hashes detect corruption, not deliberate re-authoring. Cancellation works before atomic commit, not after it.
- Writer protection covers competing application tabs at the same origin/database. Spectators show an initial read-only committed snapshot; reload for a fresh view/ownership. Lease fallback uses advancing OS time, a 15-second expiry and fenced writes; closed secure-context writers can be replaced under Web Locks immediately. Browser storage is not an authorization boundary against arbitrary privileged same-origin script/DevTools, other browser profiles or edited game files. Unknown future snapshot schemas fail closed without cleaning their metadata.
- Crew behavior remains deterministic numeric simulation with bounded sourced memories, not full human cognition. Existing Phase 2 partial knowledge-aware legacy controllers remain documented limits. Unchanged-grievance loops are suppressed and HR requires acquired source knowledge; no claim of universal belief reasoning or automatically recovered body records is made.
- New cinematic controls run on the authoritative simulation page. Android retains existing thin-client controls; no remote video-streaming service was added. Host networking/input/dependency limits from SECURITY_PHASE3.md remain. Core/Extended Universe isolation and the bounded setting are retained.

The phase must not be called fully complete until unavailable native/human gates are actually executed and reviewed. Automated implementation status and exact remaining blockers are reported in PHASE35_VALIDATION.md and FINAL_RELEASE_ROADMAP.md.
