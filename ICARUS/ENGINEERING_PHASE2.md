## Existing authorities retained

`icarus.html` still coordinates the older simulation, but new knowledge, ecology, pose and lunar logic live in modules with narrow adapters. Existing physical movement/access checks, expedition teams, clinical treatment/death, research/custody, resource accounting, field relay batteries, durable source storage, calendar and navigation remain authoritative. Source files are not bundled into another monolith. All runtime assets, including existing diagnostic dependencies and disabled Extended Universe modules that are still loaded, remain in Lite.

The Python host, Windows launcher, requirements and configuration are byte-identical to Phase 1 Lite. There is no server/API/authentication rewrite, browser-origin/port change, required gameplay approval or new agent network/command capability. Android remains a paired thin client.

## Defects and integration findings

- Hidden field observations, military archives and global exploration flags previously leaked before radio delivery. Private source admission plus delivered projections correct these paths; science retains received-evidence/material requirements. Canon edits never create discovery evidence.
- The first radio-restoration fixture had no carried supplies, so the established team-safety controller legitimately recalled it into a transport where radio was unavailable. The fixture was supplied with accounted consumables; safety logic was preserved.
- The initial browser fixture edited the pre-alias storage key. It was corrected to the actual physical core key/codec. This was a harness error, not a save-migration fix.
- Birth after lethal emergence incorrectly tried to find a now-ineligible live knowledge actor. Physical body/vehicle placement now survives zero health. Explicit host-emergence and vehicle tests protect the cause/location/memorial chain.
- The released-chamber campaign reached energy zero. A deterministic regression demonstrated that the early starvation exit prevented feeding even on a real available corpse. Feeding now precedes that exit and debits finite biomass; absent food still means no energy recovery. Diagnostic pre-fix campaigns are kept separate from accepted final campaigns.
- Tablet visual inspection found a literal JavaScript fragment in the inherited camera backdrop. It was removed. Derelict render access no longer commits telemetry connection events; docking ticks own that mutation.
- The old backup verifier initially rejected the intentional additive `knowledgeId` on legacy archives. The verifier now permits only that addition when it resolves to the matching old source and a legitimate SOL legacy entry, then compares every original domain exactly. No old field is silently ignored.
- One compatibility run recorded two transient `Invalid or unexpected token` browser errors while files were being edited. The unchanged orphan-snapshot rerun and complete stable-source rerun passed. The exact transient cause was not independently reproduced; it is not represented as a confirmed persistence defect.

## Tradeoffs and release boundary

The knowledge ledger is a source-linked information layer rather than another scientific-truth model. Legacy shipwide central telemetry remains; not every inherited personality/narrative controller has been rewritten into belief reasoning. Active knowledge remains in the snapshot and uses linear lookups; delivered message history and organism traces are bounded, while durable history persists. Broader performance indexing, autonomous body-record recovery, richer sensing/character art and authored personal content remain documented follow-up work.

Creature health/metabolic/environment rules are explicit game rules, not scientifically established species biology. Dormancy/containment does not force activity; no extraordinary footage eligibility is invented. Lunar markers are offline, range-limited and presentation-only. Automated success does not establish final release readiness or sustained story quality. See PHASE2_LIMITATIONS.md and FINAL_RELEASE_ROADMAP.md.
