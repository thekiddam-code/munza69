# ICARUS v1.2 — The Expanding Frontier

Keep the entire project together, including `web/vendor`. On Windows, install existing dependencies with `py -m pip install -r requirements.txt`, run `Start_Remote_Deck.bat`, and open the printed ICARUS PC URL. Export a JSON backup before upgrading; browser saves remain tied to the same origin/port. Existing v1.1 saves initialize the frontier without discarding crew, research or world state.

Open **Operations** for the interactive stellar map. Inspect contacts, current ship position, travel/fuel/cargo, observed opportunities and offload provenance. SOL surveys the origin's legacy sites, then autonomously travels and performs justified field/resource work. Captain course, hold-at-orbit, release and recall are optional. Paired Remote Deck tablets show nearby contacts and send commands to the authoritative PC; they do not run a second voyage.

Weekly recaps archive actual events while the voyage continues. There are no mission quotas, guaranteed scientific breakthroughs, generated rescue fuel or invented encounters. A confirmed **New Voyage** starts a new world; it is separate from weekly archives.

Read `VALIDATION_v1.2.md` for the measured acceptance table. Read `ENGINEERING_v1.2.md` for architecture, resource equations, save compression and test commands. Read `KNOWN_LIMITATIONS_v1.2.md` for abstractions, untested platforms and next work. `reports/validation_summary.json` identifies actual acceptance results; milestone JSON, campaign/conservation/diversity statistics, adverse results and portable year-end saves are packaged alongside the source. Historical v1.0/v1.1 documents remain for context.
