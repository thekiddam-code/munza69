# Phase 4.1 laptop / phone / tablet validation guide

These are instructions for physical validation, **not a claim the devices were tested here**. See PHASE41_VALIDATION.md for executed Linux/Chromium/protocol tests. Retain an untouched complete backup and the prior folder before testing. Do not disable antivirus or publish private pairing/config/TV tokens.

## Windows laptop

1. Verify the ZIP SHA-256, extract beside the old version and retain private configuration/pairing files as described in README_PHASE41.md. Close all older simulation tabs and the old server.
2. Start Start_Remote_Deck.bat. Check that the local launch guide opens. Reuse the original browser/profile/address; a localhost URL cannot read a LAN-IP origin's save. Confirm existing voyage data or deliberately import the complete backup. Never use New Voyage to recover a missing-origin save.
3. Open the host. Confirm the same crew/history/episode, normal autonomy and LINKED host status. Default mode is Bridge; test speed, forced incidents and raw psychology should be hidden. Ctrl+Shift+F12 exposes Creator and a clear banner; returning or reloading hides it again. The actual normal calendar remains 4× / approved holidays 1×, with real Monday–Sunday episodes.
4. In Creator, intentionally pause/resume and inspect the diagnostic tick. On reload, ownership should recover in the same tab; the prior unsaved pause/Creator session settings need not persist. Test a duplicated tab: it must be read-only. A different browser/origin must not replace the active server owner. Resolve the correct host deliberately before retrying, preserving original saves.
5. Customize Layout, move a visible module by its handle or arrow keys, resize by corner or numeric controls, collapse/focus/Escape/hide/library restore, save a named preset, lock and restart. Order/dimensions should persist. Reset must confirm. Change window width: mobile preferences must not overwrite desktop preferences.
6. Use the compact hologram's zoom/rotation, deck/overlay selection and room/observed-person markers. Ordinary wheel scrolling should leave the canvas; Ctrl/Alt+wheel intentionally zooms. At inner scroll boundaries the page should continue up/down. Open crew records/dropdowns, scroll a profile and let live data update: selection and scroll should remain. Classic panels may defer ambient redraw while a select remains focused; click outside when finished. The clock/controllers continue independently.
7. Test Full/Reduced/Minimal animation and existing visual toggles, with no change to simulation timing. Observe normal activity and source-backed incidents; do not force drama to satisfy a checklist.

## Phone browser and tablet browser

1. Open UMBRA at the same laptop server's LAN address and port 8765. Pair using the startup PIN if needed. Retain the installed native APK; test the browser independently first.
2. Open ICARUS. Expect HOST CONNECTED or SIMULATION PAUSED, the same episode/time/tick and received crew/mission information. Pausing the real host in Creator must show SIMULATION PAUSED, not offline. No remote game-save namespace or second physical simulation should be created.
3. Try the remote /icarus.html address, including a bookmarked query URL: it should redirect to UMBRA. The remote terminal must not initialize its own crew/world. Host navigation/hold/feasible recall commands must affect the PC's actual voyage once; queued does not itself prove execution. Creator-only speed/pause requests require the host's Creator Mode.
4. Disconnect only the phone's network while leaving the laptop running. Expect RECONNECTING/stale reports, unavailable cameras and disabled operations; the PC must continue its own world. Restore connectivity and verify the new authoritative tick/records without a reset or a stale upload. Server restart is different: reload the genuine PC host to obtain the new session/key, then verify remote reconnection.
5. Test portrait/landscape and Tab S5e landscape. Navigation, collapsible sections, crew search/follow, profile selection/scroll, camera-wall selection/focus and TV controls must remain reachable without document overflow or an obstructing remote drawer. Read source/freshness labels; unknown field contacts must remain unknown. Camera tiles are schematic projections, and incident replays are reconstructions.
6. Retest retained Engineering/Lounge/Simulator/Armory and your ordinary game controls in a safe foreground application. Original game/desktop macros intentionally affect the focused PC app; do not run risky test input in an important document.
7. Optional physical TV checks require the actual Samsung model/firmware and approval dialog. Validate basic keys first. Test/cancel the clearly labeled UMBRA-managed timer only if willing to power off that TV; keep the server running. Do not infer native TV timer/app-launch support from successful protocol serialization. Never call a fake/stubbed socket test a physical TV test.
8. If Tailscale is already configured, repeat the paired-terminal checks over its existing address/name. Do not publicly forward port 8765 or install a new tunnel merely for this checklist. Record actual connection/proxy behavior; no physical VPN test has been claimed.

## Native Android and release gates

The existing Samsung Tab S5e APK is not replaced or uninstalled. Whether it loads server-hosted assets or bundles old screens must be established from recovered Android Studio source and actual device behavior. Native rebuild remains pending source recovery; preserve application/signing identity and private settings. Record OS/browser/WebView/model versions, real usability/FPS/accessibility issues, antivirus results and device outcomes separately. A stable campaign or automated browser pass does not complete those release gates.
