# ICARUS 4.6 — Boot Screen Hotfix

This fixes startup only; it is not a new development phase. All Phase4.6 exploration and saves remain.

1. Export a complete backup from your working voyage. Retain the original Phase4.6 folder and backup for rollback. Stop the old server and close its simulation tabs.
2. Extract the hotfix Lite ZIP to a separate folder. Keep the same Windows Python environment, browser profile, hostname and port. Optional private config/paired-device/TV settings transfer follows README_PHASE46.md, with both servers stopped. The ZIP contains no personal save or pairing secrets.
3. Run Start_Remote_Deck.bat. Use Ctrl+F5 once to reload updated assets if necessary; do not clear browser/site data. Wait for actual initialization. **WAITING FOR WRITER** means storage or the server lease is still protected; it is not a countdown or an invitation to bypass the lock. A previously departed server lease may take time to expire. A genuinely live owner remains protected.
4. The authorization-key input remains available while you wait and type. Local automatic Bridge verification and writer ownership are separate. A verified key alone does not grant ownership or advance the world. Wrong-key/service errors appear in the actual status text; correct the key and use Retry authorization, or use Retry initialization to reload the saved world after an initialization error.
5. Once initialized, a prominent **ENTER ICARUS** button appears. The screen does not dismiss itself after any number of seconds. ICARUS ONLINE requires actual initialization, verified Bridge authorization and both writer protections. Until ownership is available, the screen says WAITING FOR WRITER. Explicit read-only observation remains possible after initialization; it does not grant write access.
6. Select ENTER ICARUS yourself. Neither finishing initialization, verification, acquiring a writer nor pressing Escape dismisses the screen.

If another live tab owns the voyage, close it and retry initialization. A host that loses an established server generation stays fenced and must reload current state before retrying; the hotfix never automatically takes over after ownership loss. Do not edit/delete writer records or weaken browser/server security.

Rollback: stop the hotfix server/tabs, reopen the retained original Phase4.6 folder at the same origin/profile, and restore your retained pre-upgrade complete backup if needed. No schema migration or world reset is introduced. Existing phone/tablet UMBRA pairing and the installed Android app remain; native rebuilding still awaits original source recovery.

See BOOT_HOTFIX_REPORT.md for causes, exact verification, scope and unavailable physical-device tests. The original Phase4.6 download and previous releases are retained unchanged.
