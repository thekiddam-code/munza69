# Phase 3.5 architecture

Existing physical/knowledge/resource/calendar authorities remain. Added procedural animation is a pure projection; camera retains bounded real source snapshots; chronicle evidence derives awards/exceptional criteria without forcing events; crew editorial suppresses unchanged actual disputes. The new modules do not invoke host commands or external services.

Persistence keeps schema-1 IndexedDB, its three committed snapshot revisions, indexed `history`, existing namespace and compressed compatibility cache. Writer ownership combines Web Locks when available with an IndexedDB lease and monotonically fenced token in every durable write transaction. In insecure LAN contexts IndexedDB claims are atomic; leases expire after 15 seconds and renew every three. Closed secure-context writers can be replaced immediately under Web Locks. A losing/stale tab cannot save or advance physical ticks; remote command/telemetry ownership is also gated. Its initial committed snapshot stays read-only until reload. Arbitrary same-origin script/DevTools can directly alter browser databases; this policy prevents competing application tabs, not a privileged malicious script.

Streaming .ndjson export reads cursor batches of 128 records, hashes each chunk with portable SHA-256, links an ordered hash chain, and emits a final count/manifest. The world snapshot is separate from history. File System Access streams bytes to a writable file; unsupported browsers use Blob parts, retaining encoded file bytes until download (not constant-memory output). The existing JSON exporter remains for compatibility/rescue. Export refuses to claim completeness if required sources are missing.

Import validates schema, chunk hashes/order, unique IDs, final manifest and required source availability. Staged rows live under session keys in the existing metadata store; no database-version bump invalidates old readers/tests. Final history merge and world/head commit share one fenced atomic IndexedDB transaction. Cancel/error before commit discards staging and keeps the original world. A crash leaves abandoned staging, removed by the next writer at startup. Original committed revisions and history remain for recovery. Intentional rollback chooses a new event namespace before commit; no prior event IDs are rewritten. Post-commit migration is additive and uses the existing restore path.

Transfers freeze physical controllers/remote commands while showing progress, then normal bounded catch-up resumes. Cancellation is available until the atomic commit begins. Legacy monolithic JSON is still parsed as a whole (128 MiB pre-existing limit), then history is staged incrementally. New streamed backups avoid that format limit, with a 64 Mi UTF-16 code-unit buffer bound, 128-row chunks and schema checks. World/knowledge state itself still grows; this work streams full archive history, not every live state component. Import requires functioning IndexedDB; labeled legacy rescue export remains available if durable storage fails. SHA-256 detects corruption, not author identity or intentional file edits.

Core art, thin-client Android authority, local port/origin and Python host/dependencies remain unchanged. All new fields are additive; old cinema records gain only an empty source-frame buffer. Old films remain intact. Tests and evidence distinguish real browser execution, explicit failure fixtures, emulation and untested native hardware.
