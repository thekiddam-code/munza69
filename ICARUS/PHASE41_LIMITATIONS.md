# Phase 4.1 remaining limits / release gates

Browser/server implementation is subject to the actual reports in PHASE41_VALIDATION.md. Do not infer a full physical-release acceptance claim from automated tests.

- Physical Windows launch/input, Samsung Tab S5e/Android/Wi-Fi/WebView, Samsung TV, actual Tailscale routing, antivirus scanning, screen-reader/native GPU/FPS and sustained human usability are **not run** here. Protocol HTTP/SSE, Chromium phone/tablet emulation and stubbed TV/desktop input are distinct.
- The working installed APK is preserved; native rebuild/update is **pending recovery of the original Android Studio project**, not permanently unsupported. No replacement APK or signing/application identity is introduced. Bundled native screens need source recovery to adopt new web presentation.
- Keep the original browser origin/profile, or explicitly import the complete backup. Browsers cannot automatically read another origin's save. Close older host tabs before upgrade; old binaries cannot retroactively implement the new fence. Existing legacy standalone copies can still run outside this server's control.
- The server/browser must be running and the PC awake. Background throttling or suspension may temporarily expire freshness. Same-owner heartbeat can renew only if no newer host took over. Server restart changes the bootstrap key/session and requires host reload. A genuinely losing owner remains stopped; no stale takeover is forced.
- Acknowledged delivery is at-most-once per session, not an atomic world/server transaction. Commands can be lost on a crash between receipt marking and application; they expire rather than replay into a replacement world. Queued/socket-sent does not mean physically executed. Legacy protocol-1 hosts retain their original weaker queue contract.
- Personal clinical/psychological assessments appear only when actual received records exist; this batch does not fabricate diagnoses or expose private numerical traits. Source lists are bounded summaries, not replacements for full archives. Unreceived field progress remains unknown.
- Cameras are schematic projections, with actual receiver/coverage limits, not video streaming. Existing state-frame incident replays remain reconstructions. Actual recording streaming and new kill-camera capture are deferred. Camera-wall selected rooms/columns persist; native manual per-tile CSS pixel resize is not persisted independently of its workspace module dimensions.
- The workspace is a non-overlapping responsive grid with saved order/span/height, not arbitrary overlapping desktop windows. Each major catalog module can move/resize/collapse/focus/hide; existing specialist pages remain. Native select-popup appearance and screen-reader behavior need device testing. Workspace editing should be locked before normal operation.
- Full/reduced/minimal animation controls CSS effects; canvas retains state-driven rendering. Native FPS/energy use and unusually long saves still need sustained device profiling. Existing large-history growth and legacy monolithic import parsing are retained; no fabricated performance certification.
- Existing trusted-LAN HTTP, authorized desktop input and optional inherited Samsung certificate omission remain documented. No automatic public exposure, VPN installation, host shutdown, antivirus bypass, voice/push or cloud simulation is added.
