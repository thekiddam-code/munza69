# v1.1 limitations and next batch

## Scope and limits

- Acceptance is a measured ninety-day demonstration under seed 1001, plus deterministic and adverse fixtures. It is not proof of every seed, arbitrary user action or indefinite operation. See the actual report statistics and validation summary.
- All major stores and conversion inputs are finite and audited. Recycling uses normalized abstract yields (idealized water/CO2 recovery and 98% process-scrap recovery), not element-by-element chemistry or a realistic energy/food life-support calculation. Starting fuel/minerals/nutrients are finite; indefinite voyages require additional procurement beyond the fixed maps.
- Field topology remains two finite 25-cell locations. Once accessible evidence/objectives are exhausted, SOL stops dispatching rather than fabricating contacts. This build does not create a procedurally infinite universe. Recovered ice is stored but not processed; water replenishment is reclamation.
- New expeditions contain two people, share one field route and one transport, and have per-person conditions and buddy-return records. Independent tactical movement, arbitrary squad sizes, ranged combat and detailed EVA positioning are not implemented.
- Independent measured support confirms a narrow spectral/material family. It does not prove extraterrestrial origin or safe life reconstruction. Lazarus remains a fallible long-term research program; safe crew revival is not implemented.
- Old saves can preserve only the world that v1.0 actually saved. Earlier weekly losses cannot be reconstructed. New clock timestamps are not downgrade-compatible; historical text labels remain legacy labels. New Voyage is an explicit full scenario reset, separate from ordinary weekly archives.
- Journal, field history, intervention and archive retention retain bounded windows. Local browser storage is finite; export backups and archives for campaigns far beyond the tested duration. A ninety-day pass is not a permanent-storage guarantee.
- The existing HTML still owns much of legacy crew psychology, room physics and rendering. New mechanics are modular, but this batch does not fully rewrite the legacy simulation. Complex environmental rescue remains the established routed model.
- No new combat or lethal-footage generator is provided. Event recaps retain source references and reconstruction labels. Legendary selection remains empty unless a genuinely qualifying recorded encounter exists.
- Physical Windows game/input controls, tablet pairing, Samsung TV commands and an exhaustive visual screenshot suite were not exercised in this Linux environment. The host code is unchanged. Browser integration does test real simulation and selected intervention UI controls.

## Recommended next batch

1. Run multi-seed 180/365-day Monte Carlo balance and storage tests, including compound failures, diminishing feedstock and partial crew loss. Add archive streaming/rotation with explicit retention controls.
2. Add new physically justified contacts and finite mining/ice-processing/depot opportunities, with contracts or sensor evidence before dispatch. Expand the economy's recipes, energy priorities and nonideal recycling losses using measured balance targets.
3. Extract atmosphere/clinical triage and assignment arbitration from the HTML. Add backup import/export and physical-host protocol integration tests, with supported hardware stubs.
4. Extend independent scientist review and assay controls without turning spectral/activity support into automatic Lazarus success. Add instrument calibration and distinct assay reproducibility statistics.
5. Expand optional team size and tactical movement only after shared-route/gear conservation fixtures pass for every transition. Add encounter/recording provenance before any combat playback feature.
