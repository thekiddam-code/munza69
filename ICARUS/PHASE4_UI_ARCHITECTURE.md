# SOL command interface architecture

`command-ui.js` owns read-only routing, section visibility, accessible navigation/history, help, live control status and the user-facing testing form. It accepts narrow callbacks inside the existing lexical simulation closure. It creates no second controller, physics loop, save namespace, host service or network request. Internal page aliases retain existing callers.

Existing DOM components and their handlers move once into logical homes. Home keeps its original widget catalog, device preferences and same-node mounting; widget origin markers are updated to new logical homes. Normal page navigation deliberately ends an interaction before restoring widgets. There is one camera and one currently mounted LAZARUS procedure view. Existing field-console renderers and physical access constraints remain.

`anthology-ui.js` separates Bridge directives, Missions logistics, Chronicles story records and Settings preferences. Preference nodes survive ordinary live refresh; imported replacement worlds refresh both values and callback binding. `living-frontier-ui.js` keeps its original persistent selection/playback view state while placing registry, rescue, memory, Sunday cards and durable-save components in their respective sections. Explicit selection repaints; ambient refresh does not discard a focused edit. Source labels and individual knowledge authority remain unchanged.

`command-ui.css` supplies shared straight control geometry, muted translucent amber gradients, cool inactive gradients, focus, responsive layouts and touch minimums. Obsolete generic geometry/fill/glow declarations were removed from the HTML style source; this is not another global important-override stack. Legacy panel geometry/ship-specific instrument styling remains. The only new important declaration enforces actual `hidden` section semantics against legacy display rules.

The production `calendar.js` pump optionally accepts an explicitly validated 1/5/20 test rate. It changes physical-minute accumulation only; holiday recognition, real-week synchronization, monotonic tick, work budgets, pause and six-hour recovery remain. The page owns an unsaved session rate. Mode transitions first drain prior elapsed time using the old rate; a pending recovery budget or read-only/backup transfer blocks a transition. Pause settles the previous pause state. Reload returns normal. Physical `step` and `fieldTick` remain the only per-minute authorities. No extra TV/host command is generated by test mode.

New operator directives use existing `frontierCommand`/mission intervention APIs and log actual accepted/rejected commands with `authority:SOL` and `controlLayer:operator`. Historical captain sources are not rewritten. Status is derived from actual holds, autonomy switches and scoped mission commands; Release resumes existing autonomy while respecting physical travel and safety.

Core save version 2, backup format 1, IndexedDB schema 1, namespace, source IDs and writer fencing remain. Backup appVersion is 1.8.0-phase4. Full archive/streaming machinery is retained, not redesigned. Prior knowledge/ecology, relationships, research, resources and calendar controllers retain authority. Core and Extended remain isolated.
