# Phase 4A architecture

Existing authoritative ICARUS controllers, save schema/namespace, sources and time rules remain. No second simulation runs in UMBRA. `web/index.html` remains the existing entry point; existing department IDs/actions and pairing persist. Existing Engineering/Lounge/Simulator/Armory/game functions are reused.

`camera-sprites.js` extracts the existing standard and 51st-State functions without changing their generated bytes. ICARUS wraps those shared functions; the UMBRA viewer uses them over actual observed actor state. `companion-view.js` is a pure bounded projection: real receiver/visibility gates, current ship cameras only, genuinely received last field reports, unconfirmed deaths withheld until known, and public source-linked activity. It does not learn facts, alter RNG/state or capture fictitious video. Its camera grouping is a schematic state view, not a screen recording. The existing PC publishes it through the authenticated bounded telemetry route.

Backward compatibility: original endpoints, bearer-token hashes, pairing PIN, port, action bodies and TV key strings remain. Legacy GET `/api/icarus/telemetry` strips the new optional companion object; the new browser explicitly opts in using `?companion=1` (and falls back on older servers). The legacy `/api/tv/key` response stays exactly `{message: 'TV: …'}`. New `/api/tv/status` reports adapter capabilities/send status; `/api/tv/timer` is authenticated/Origin/body bounded. New metadata never becomes an unrestricted command channel. Existing companion speed commands remain diagnostic; the genuine development clock is on authoritative-PC Settings → Testing and its reported rate is now accurate.

`tv_service.py` owns one reusable existing Tizen socket, a dedicated lock (TV timeouts do not hold the global simulation/input lock), send errors and a volatile real-monotonic countdown. It uses only the original allowlist/factory/token persistence. It makes one expiry attempt, cancels on config/owner unpair/server shutdown, rejects obsolete generations and skips callbacks over 60 seconds late. It never schedules OS shutdown/tasks or native TV timer settings. Socket availability is not a liveness/TV execution acknowledgment.

`web/umbra/`: `icons.js` bundles font-independent paths; `layout.js` validates bounded local profiles and undo drafts; `lounge.js` reuses TV controls and adds explicit editing/timer/status; `sol.js` consumes the single existing bounded poll, filters/chooses covered camera and crew data, labels provenance/staleness; `app.js` keeps existing shell/auth/functions and adds guarded default-off decorations/fictional archive. `umbra.css` replaces the accumulated UMBRA styles with a cool corporate OS theme and intentional window-based phone/tablet layouts, without touching ICARUS's theme. Legacy display/wake preferences remain stored; native wake behavior still requires the existing app sources.

Per-device keys are UMBRA-only. Profiles cap at eight per orientation and 32 controls; undo caps at 20; edited commands remain inside the existing protocol library and server validates again. Six GIF/PNG pairs are memory-cached after loading (each file bounded at 150 KB); only one GIF is displayed at a time. No CDN/fonts, automatic sound, fake event or game/TV command is connected to decoration. A fresh browser bootstrap still requires the PC server; native asset packaging is pending original-project recovery.
