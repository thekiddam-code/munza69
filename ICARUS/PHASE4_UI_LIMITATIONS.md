# Phase 4 known limits and remaining gates

The interface and development clock are implemented, but full Phase 4/final release acceptance is not declared. Physical Windows, Tab S5e/Android, Samsung TV, Wi-Fi, antivirus and sustained human usability/contrast/content review cannot be certified by this Linux environment. Browser tablet/phone emulation is reported separately.

Procedural camera art, source-backed templates and chronicles retain Phase 3.5 audiovisual limitations. Ship → Cameras links to the one actual Bridge camera rather than duplicating it. Research renders existing science models; no new intelligence or omniscience is introduced. Some specialist field consoles retain their older nested layouts and technical labels. Additional human refinement of density, large rosters, specialist dialogs and sustained tablet use remains.

Development acceleration intentionally alters the current voyage, uses no cloned test namespace and resets to normal on reload. The persistent banner/confirmation does not make testing reversible. Keep a backup before experimenting. Existing explicit Advanced creator/director tools remain separate from autonomous simulation and can change test conditions deliberately.

Backup/migration UX polish is deferred by user priority, not canceled. Existing storage/history growth, legacy whole-JSON parsing, Blob fallback memory, same-origin browser storage limits, mixed-version tabs and device-origin migration constraints remain as documented in PHASE35_LIMITATIONS.md. No infinite-memory or platform-security claim is made. New controls use existing permissions; trusted-LAN HTTP/host macro/TV limitations remain.

Tests and actual campaigns, including superseded failures, are recorded in PHASE4_UI_VALIDATION.md and repository reports/phase4. Missing native/human gates prevent a full completion claim even if all executable tests pass.
