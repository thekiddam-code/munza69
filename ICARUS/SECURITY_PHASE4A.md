# Phase 4A static security review

The browser/server extension retains the existing trusted-LAN HTTP listener/port, PIN/bearer-token hashes, dedicated ICARUS host key, same-Origin/body validation, predefined game actions/macros and the original TV key allowlist. New timer/status routes use the same paired authentication. Camera data is opt-in on the same telemetry route; legacy responses retain their old shapes. No Tailscale, push, voice, public forwarding, arbitrary command editor, native replacement app, new process/service or network port is introduced.

`tv_service.py` uses standard Python threads/monotonic time and the existing TV connection factory. The new managed sleep timer can intentionally send the original TV Power Off after explicit scheduling. It cannot power off the host PC, run shell commands, add scheduled tasks, register services, edit firewall/registry/antivirus or execute arbitrary keys. Generation/owner/target/restart/late-wake guards and no automatic failed-send retry prevent stale shutdown attempts. Timer state is not persisted across restart. Normal sends are serialized and sessions reused; device execution is not acknowledged by the existing protocol.

Retained security-relevant behavior: the server intentionally exposes authenticated PyAutoGUI keyboard/mouse/text actions to paired devices; macros can affect the focused host app/clipboard. It listens on 0.0.0.0:8765 over unencrypted HTTP for a trusted LAN. Optional TV WSS uses a configured private IPv4 address and inherited certificate-validation omission (`ssl.CERT_NONE`) for compatibility; LAN impersonation remains a risk. No new external service is contacted by game agents. Existing launcher starts local Python and does not install/elevate/disable protection. Dependencies remain unchanged version ranges, not a hashed transitive vulnerability audit.

Expected writes remain local config/pairing/TV-token files, browser saves and client preferences/downloads. Private pairing/TV files are excluded from distributions/Git; installation instructions explicitly retain them locally. Per-device profiles are bounded, validated against an existing TV-only library and server checked again; labels are text, not command/HTML execution. Critical icons/sprites/assets are local. The six GIFs are user-supplied fictional assets; reduced-motion PNGs decode real first frames. Assets are bounded in memory and cannot become real simulation records or commands.

Static checks, syntax, file hashes, endpoint tests and explicit stubbed I/O are not antivirus certification or penetration testing. Windows Defender/other antivirus engines and physical hardware are unavailable here. No protection is disabled or bypassed. The original Android app/signing keys are untouched; native package/security validation awaits its recovered source.
