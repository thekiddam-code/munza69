# Phase 4.8B architecture, storage and security

## Modules and interfaces

- sound_library.py owns canonical PCM validation, metadata, hashed immutable clip files, revision checks and atomic/fsynced commits. It uses soundboard_data adjacent to server.py, outside web/ and outside ICARUS saves. Maximum 30 seconds per sound, 64 clips / 64 MiB. Corrupt libraries produce errors and are never reset. A metadata-commit failure removes only the newly staged clip; a crash during deletion can leave an unreferenced file rather than destroy another sound. No automatic orphan deletion is performed.
- sound_import.py reads only user-requested public HTTPS Myinstants pages and their main audio references. Main og:audio / main-button metadata is preferred; unrelated recommendation buttons are never substituted. Host, path, scheme, DNS and redirects are restricted. Page limit 512 KiB, source audio 3 MiB, two simultaneous imports, four requests per minute per paired owner, eight-second network timeouts. No JS execution, account/extension automation, access bypass or downloaded executable. The explicit permission declaration is not a legal/licensing verification.
- sound_output.py is Windows render-only waveOut. Explicit device ID/name, PCM buffer, clip-local volume/fades, one owned stream, bounded worker lifetime and explicit stop/error handling. It never calls waveIn, captures a microphone or changes any default/Sonar route. Buffers are retained and further playback blocked if a broken driver refuses release, avoiding freeing in-use memory; restart is then required. Actual Windows driver behavior remains a hardware gate.
- sound_service.py coordinates library/output/import operations. Host play/stop/output changes serialize on a dedicated lock, separate from ICARUS input. Successful play requests are deduplicated per paired principal/requestId for 120 seconds, max 128 receipts. Receipts do not survive server restarts; the client does not auto-retry or queue offline playback. Other paired terminals can stop host playback intentionally.
- umbra/soundboard.js and soundboard.css implement the native drawer, import/edit/reorder/filter UI, terminal-only Web Audio preview and canonical conversion. One pointer/click route; public host playback and private AudioContext.destination playback are separate functions. No getUserMedia, audio-input enumeration or microphone permission request.
- sound-gestures.js explicitly cancels movement/scroll/release/lost capture, blocks public ghost clicks after hold, and keeps keyboard activation accessible. sound-cache.js owns only umbra-sound-library-v1; canonical blobs/metadata persist separately. Hot decoded buffers cap at four and fetched blob cache at eight; stale disk entries are pruned on sync. Caching failures never delete the PC library. No global IndexedDB clear or simulation backup mutation.

## API and authorization

Existing PIN/bearer pairing, same-origin POST validation and token revocation remain. Every new API is paired-only, no-store; audio is served as audio/wav with nosniff from an ID lookup only. No public/static sound directory, token-in-URL, arbitrary file path or executable argument is accepted.

GET /api/sounds/library returns metadata, render devices, selected output and actual player status. GET /api/sounds/audio?id=… returns the checksum-verified original canonical library clip. POST /api/sounds/import accepts bounded canonical WAV base64 and metadata/permission/revision/source. POST edit/delete/reorder/output use exact fields and optimistic revisions. POST play takes only id/requestId; POST stop accepts an empty object. POST link takes only URL/permission and returns permitted main audio for browser conversion/preview. There is deliberately **no host private-preview endpoint**.

The import POST body limit alone is 2,000,000 bytes; existing ICARUS telemetry and all other request limits remain unchanged. Upload input is canonical 24 kHz mono PCM16, not arbitrary compressed files executed by the server. Browser metadata/duration validation precedes decoding; unknown/long/unsupported files are rejected. Client cancellation invalidates late preview/import results. Blob/decoder/HTML source errors are actionable rather than replaced by fabricated audio.

## Network, commands and system changes

The only new external network access is explicitly requested, allowlisted Myinstants HTTPS reads. Public page/source availability can change; no service is a playback runtime dependency after import. File upload requires no external service. No new subprocess command is used at runtime, no package/driver is installed, no registry/default-device/Sonar/power/fan/antivirus setting is modified. Existing requirements.txt is unchanged. Tests use ffmpeg solely to generate an owned sine-wave MP3 fixture; ffmpeg is not a runtime dependency and is not bundled.

waveOut opens only the selected render device and closes UMBRA-owned buffers. It is not a serial voice path, but physical voice continuity/private acoustic isolation cannot be certified from code inspection/mocks. If the tablet/PC audio is already captured by another application, UMBRA cannot undo that configuration silently. Actual private-preview leakage and microphone survival tests remain pending. Normal playback never silently falls back to terminal audio when the host fails.

## Compatibility and separate repair

No simulation engine, clock, crew, research, expedition, drone, camera capture, save namespace or world-schema module changes. The browser/server extensions preserve existing contracts. No voyage migration is necessary. Keep the private library directory during upgrades and rollback; it is intentionally not contained in world backups or project ZIPs. The separate Easter egg commit only restores client rendering/activation and retains opt-in preferences; see EASTER_EGG_VISUAL_INVESTIGATION.md.
