# Rendering decision and original assets

The current renderer uses DOM/SVG room backdrops, procedural crew rigs, source-backed Cinema capture and an incremental schematic remote wall. Those remain compatible; the new camera surface uses native Canvas 2D at 384×216, cached original 36×54 character rigs, shared layered room recipes, nearest-neighbor CSS and separate presentation clocks.

Research: official GitHub repository metadata queried during this batch (retained in reports/phase42a/baseline/rendering_research.json). LittleJS: MIT, lightweight sprite/tile support, but a second loop and dependency are unnecessary for five canvas surfaces. Phaser: MIT engine, rich scenes/tilemaps/mobile support, substantially broader integration and lifecycle than needed. Phaser examples: repository API reports no blanket license; example artwork is not assumed reusable. Excalibur: BSD-2-Clause, typed actor/scene framework; adds another actor ownership layer. Pixelorama: MIT editor/export workflow, not a required runtime; useful for future art refinement. No library installed and no third-party code/art imported, so no new dependency or asset-license burden. Sizes in metadata are repository sizes, not runtime bundle measurements.

Original artwork is implemented in pixel-camera.js: role uniforms, skin/hair/recognizable established details, layered industrial walls, doors, pipe runs, machinery, medical beds, consoles, tables and state-driven lighting. Film/game references guide broad visual direction only; no extracted sprites, ROMs, backgrounds or proprietary code. These are procedural sprite recipes cached as frame canvases, not hundreds of imported sheets. Production art fidelity remains a human review gate.
