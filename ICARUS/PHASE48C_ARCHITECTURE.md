# Phase 4.8C preservation/audio/palette architecture

## Verified storage model and upgrade behavior

4.8B `server.py` constructs SoundService at ROOT/soundboard_data. A successful Add Sound posts canonical PCM and metadata to that service; library.json and UUID.wav are fsynced/atomically committed. Button IDs/order and all saved sound settings are server-side. Browsers cache metadata/blobs in a separate IndexedDB database. They do not own a second authoritative library. This model was verified through source, populated schema-1 fixture restarts and real HTTP PC/tablet/phone browser contexts. **The user's installed Windows directory is not accessible here; its actual sound count and backup have not been verified.**

No format migration is required. Existing WAV bytes and schema-1 library.json remain. audio_profile.json is optional, separate, and ignored by older B code. Upgrades must carry the complete private directory; project ZIPs deliberately never contain it. A missing/older server library cannot replace/prune an already populated terminal cache in the new UI. A missing library also blocks C calibration/profile writes. No recovery deletes originals. A legitimately older restored backup may require deliberate cache recovery after verification; never clear the world database to solve it.

## Added code

- sound_backup.py: standalone standard-library snapshot/inventory/verification. Captures all regular files (including unknown/orphan files), rejects symbolic links, limits the source to 128 MiB, verifies ZIP CRC and SHA-256/size per file, compares source inventory again before atomic publication. Library reference errors are reported without discarding files. No restore/extraction or source deletion. CLI `--require-existing` fails for empty/wrong folders; the batch helper uses it.
- SoundService preservation gate: before first mutation/profile write, require a verified snapshot under its library lock; fail closed on missing/bad source references or disk errors. Empty brand-new library initialization is distinct from backing up existing data. Explicit paired backup/export is available. No automatic backup deletion. Private data/backups are gitignored.
- audio_capture.py: Windows legacy waveIn enumeration and a fixed five-second PCM buffer. Capture only follows authenticated host-local consent; no automatic sampling, fallback device or Windows/Sonar configuration API. Device identity rechecked. Cancellation is checked before input open/start and buffers are stopped/reset/unprepared/closed. A broken driver retaining memory disables further sampling until restart. Raw voice stays in memory; no voice file or audio response endpoint.
- audio_loudness.py: mono BS.1770 K-weighting, 400 ms windows/100 ms hop, -70 LUFS absolute and -10 LU relative gates. Short clips use available-length blocks and are flagged approximate. Clip processing targets measured speech plus offset (default -3 dB), keeps saved volumes intact with 35% nominal, caps boost at +6 dB, protects sample peaks (default -1 dBFS) using 10 ms lookahead, 2 ms attack/80 ms release and a final sample guard. It is not certified R128 multichannel or true-peak/intersample limiting. No peak-only perceived-loudness claim.
- audio_service.py: opt-in profile and bounded four-clip transient PCM cache, read-only Sonar name diagnostics, calibration and separate level-only sampling. Level tests cannot overwrite speech calibration. Capture cancellation is allocated before backup, so Emergency Reset during a slow backup cannot open a mic later. Normal close releases owned resources and preserves preferences; explicit Emergency Reset disables DSP. No live voice is routed through UMBRA.
- audio-controls.js: existing soundboard extension for backup, endpoint inspection, explicit Sonar Aux clip-output selection, host-local consent, calibration/meter, normalization and Emergency Reset. Backup finishes before the UI asks for speech. The pending UI operation is invalidated by reset. No actual Sonar mixer/per-app setting is written. Capture roles from truncated names are not invented.
- anomaly-palette.css: component-only historical colors; original GIF/PNG bytes, existing triggers, preferences and world state stay unchanged.

## API authorization and privacy

All new routes retain existing bearer pairing and no-store responses. POST same-origin and existing size guards remain. No general paths/arguments are accepted.

GET /api/sounds/library adds storage location/presence and profile status without converting the library. POST /api/sounds/backup and GET /api/sounds/backup?id=… create/download verified server ZIPs; IDs follow the generated UTC/hex grammar, not arbitrary paths. Backup download streams data and requires pairing. Backup snapshots are sensitive and remain outside web/ and Git.

GET /api/audio/status lists actual available legacy endpoints, the owned profile and truthful routing limitations. GET /api/audio/processed?id=…&volume=… returns transient processed sound-effect PCM (never microphone samples) with the actual preview gain. Original audio remains on /api/sounds/audio. The host player uses the same processing function; a stale client cannot accidentally apply full gain when processing was disabled remotely. Processed preview does not send a host-play command and fails explicitly without the host rather than silently substituting raw audio. Unsaved candidates retain labeled raw preview.

POST /api/audio/prepare verifies preservation before sampling. POST /api/audio/profile permits only bounded owned DSP settings; no client-injected speech reference. POST /api/audio/calibrate and /api/audio/measure require pairing, local-host identity and explicit consent, fixed duration, and a single active input buffer. The latter returns levels without saving calibration. Only numeric metrics/labels are sent. POST /api/audio/reset stops owned resources/cancels pending input and disables DSP. No endpoint changes Sonar, Windows defaults, per-app inputs or physical mic routing.

The existing imported-clip limit/body cap remains. No new cloud service or external runtime request is added; only explicit official help links. No new pip dependency, virtual driver, device-default command, registry write, audio enhancement toggle, privilege escalation or antivirus modification. Existing Windows launcher/monitor commands remain unchanged. Native driver execution cannot be certified on Linux.

## Source-backed Sonar boundary

See SONAR_ROUTING_AND_VALIDATION.md. The documented independent optional route uses Sonar Aux plus Mic in Stream Mix and a receiving app's Sonar Stream input. The user reports Sonar Microphone instead. Those cannot be equated by endpoint name or a meter reading. The build can explicitly target a uniquely detected Aux for its own clips; it never enables/channels a stream or changes the receiving app. Full combined-audio verification, physical mic switching inside Sonar and preservation of exact current external settings need actual Windows review/user decisions. `injection_verified` stays false. No untested serial UMBRA mixer is substituted.

## Persistence/performance/remaining gates

Storage backup locks only the sound library, not simulation writer/tick state. DSP is on-demand and cached; there is no continuous mic capture or server-side live voice transport. World/save/crew/clock/research/expedition/recording modules are unchanged. Export the voyage separately and retain original folders. Hardware input/output, privacy/loopback/voice-survival tests, actual existing-library backup verification, native Android source recovery, TV/Tailscale and antivirus checks remain pending. Full historical/campaign matrix is not rerun for this companion-only change.
