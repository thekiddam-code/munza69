# Combined payload regression

Static review identified two carriedMass properties in expeditionEnvironment. JavaScript retained the latter specimen-only callback, replacing the earlier recovered-drone callback. The same duplicate existed in ca2fcff before Phase4.9. New live containers had correctly accounted one mass unit, but a recovered four-unit drone could be omitted from a combined payload, making later sampling/recovery capacity decisions too permissive. This is a capacity-accounting defect, not evidence that resource stores were duplicated.

The repair consolidates active specimen/bulk and recovered-drone mass in ICARUSExpeditionOps.carriedMass and registers one host callback. Stored/archived items and drones assigned to other missions do not count against this manifest. The existing load/capacity methods, paid inventories and physical recovery remain authoritative. No item, resource, character, time or equipment condition is created or changed by the pure mass query.

A deterministic unit case places the payload at39.6 of40 units, including a live container and recovered drone; another one-unit collection must be infeasible. A real-browser regression reads the actual host callback and verifies a carried test chassis contributes four units to both carried and total mass. This explicitly labeled load fixture is not a normal discovery or footage. The24 affected expedition module cases and host regression passed. The entire suite and final campaigns are rerun against the correction; pre-correction campaign prefixes and the completed10101 90-day run are retained as development evidence, not final acceptance for the delivered runtime.
