# v1.4.1 limitations

This is a focused stabilization, not a declaration that ICARUS is a finished commercial release. FINAL_DESIGN.md and FINAL_RELEASE_ROADMAP.md remain the product boundary. No unlimited resources, invulnerability or guaranteed rescue is introduced.

- Repair/access logic uses normalized costs, condition/progress and the existing discrete corridor model. A jam can be worked from the reachable near-side corridor; captain-sealed rooms and unsafe pressure/fire remain genuine barriers. It does not implement a new firefighting, depressurization, breach-entry or towing system. Some emergencies can be unrecoverable.
- One reserved native responder per fault protects coverage. It is a bounded safety policy, not a global optimal workforce planner or multi-engineer task scheduler. Actual health, fatigue, morale, route, parts and personal effort still limit recovery. A different combination of faults or crew loss can defeat it.
- Forecasts use a rolling sixty-minute measured rate and immediate upstream-fault checks. They do not predict random future failures, exact long-term production demand or every shortage combination. Unknown/steady horizons are not infinite-supply promises.
- Native/preventive/hatch repair costs now consume actual existing pools. Existing older progress is retained; there is no attempt to retroactively bill v1.4 work that was free under the old rules. Legacy paid spare carrying tokens are recognized; arbitrarily edited inventories/cost flags are unsupported.
- Upgrading preserves existing deaths and unresolved damage. Recovery tests use an actual pre-collapse snapshot, rather than rewinding the player's world or restoring deceased crew.
- Exact replay specifications include the initial seed, initial saved world, external actions and checkpoint/rollback profile. The original seed-1001 failure was reproduced with day-30/day-90 reloads; an uninterrupted v1.4 same-seed run survived. Different journal rollback histories can select different later anthology branches. This update does not claim identical narratives for every different checkpoint profile.
- The small existing anthology vocabulary, numerical crew psychology, broad observation-to-case narrative linkage, specialist-page consolidation, audio/cinematic work, streamed backups and multi-tab writer arbitration remain prior roadmap work. Stabilization adds no new encounters or planetary/faction/economic expansion.
- Significant source history still grows with actual activity. Three rolling IndexedDB snapshots and bounded recent views do not provide unlimited storage. Large JSON imports/exports allocate browser memory. Off-device complete backups remain necessary for browser-origin/profile deletion. Existing core and Extended Universe save separation is preserved.

Automated validation uses Linux Chromium, real IndexedDB, desktop/tablet viewports and a real loopback authenticated bridge with physical desktop input stubbed. Physical Windows/Android/TV, Firefox/Safari, real LAN-disconnection, hostile concurrent tabs and sustained human usability/content review are untested. Passing selected long seeds does not guarantee every seed survives or certify final-release readiness.

See reports for actual deaths, shortages and unrecoverable cases. Synthetic adverse setups are labeled; they are not presented as natural encounters. The root-cause report distinguishes intended danger from confirmed access/dispatch defects and independently identified scheduling/accounting problems.

The existing local ore controller can authorize many small harvests when inventory dips just below its fixed 300-unit reserve target. These have new measured deficits, finite deposits, paid launch supplies and actual returned receipts; they are distinct from the fixed exhausted-objective navigation loop. Batching/hysteresis and stronger estimates of expedition overhead remain balance work, and are not claimed solved by this stabilization. Existing process-scrap recycling returns up to 98% of consumed material in normalized game units; gross recovered ore includes repeated recycling, not solely fresh extraction or an infinite source. The accounting audit separates those sources.
